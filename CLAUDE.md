# Jatta

Jatta (каз. «заучивай») — ИИ-учебник английского на Kotlin Multiplatform (Android + iOS), без сервера.
Научная основа и механики М1–М23: `docs/mechanics.html` (опубликовано: https://claude.ai/artifact/1rr8HKEgen5H7N3BP9XS3j).

Лицензия: GPL-3.0-or-later (`LICENSE`) с дополнительным разрешением по пункту 7 GPL на связывание с Google ML Kit. Текст разрешения и чужой код/данные — в `THIRD_PARTY_NOTICES.md`: при заимствовании кода или данных добавлять туда источник и лицензию. Новую закрытую библиотеку без отдельного разрешения не подключать.

## Модули
- `engine` — чистое ядро: FSRS, план дня, очередь занятия, лестница, отдых. Без часов, базы, сети и платформенных API.
- `study` — всё вокруг движка без UI: формат и загрузка контента, упражнения, проверка ответов, хранение прогресса (`LearnerStore`, JSON + журнал `answers.jsonl`), ход занятия (`StudyController` → `Screen`), проверка свободных ответов моделью (`judge/`).
- `shared` — интерфейс на Compose Multiplatform. Только рисует `Screen` и вызывает `StudyController`. Оформление — `Theme.kt`: киберпанк в двух палитрах — тёмная (неон на почти чёрном) и светлая (те же оттенки темнее, чтобы читались на белом); скошенные углы, сетка, компоненты `NeonButton`, `Panel`, `Label`, `NeonBar`. Цвета брать только через `Neon.*` (текущая палитра), не литералами. Выбор темы — `ThemeChoice` (система / светлая / тёмная) в `SavedState`, переключатель на главной; Android подстраивает иконки системных панелей через `onDarkTheme`. Шрифты Exo 2 и JetBrains Mono (OFL, с кириллицей) в `src/commonMain/composeResources/font/`; эта папка склеивается с `content/` задачей `syncResources`.
- Индикаторы: на главной «Память» = сколько единиц держится в памяти (вспомнятся завтра с вероятностью ≥ 85%), а не «пройдено»; у тем — то же по теме; в занятии — шаги (`Steps`), полоса только растёт.
- `androidApp` — `MainActivity`. iOS: `MainViewController()` в `shared/iosMain`, Xcode-проект появится после установки Xcode.

## Контент
- Источник — `content/en/`: `course.json` (темы по порядку) и `topics/<id>.json`. В приложение он копируется задачей `syncContent` модуля `shared`.
- Слово: `en`, `ru`, `note`, `examples` с `gap`. Правило: `ru` — правило одной строкой, `note` — объяснение, у примеров есть `gap`, `cue` и `wrong` (неверные варианты для выбора).
- `rank` (М8) — ранг слова в NGSL 1.2 (`sources/ngsl/`, CC BY-SA 4.0, в приложение не попадает). Слова нет в NGSL — `rank` не ставим. `ContentTest.wordRanksComeFromNgsl` это проверяет.
- Курс — около половины учебника уровня Intermediate (English File Intermediate: 20 уроков, ~20 тем грамматики, ~20 тем слов, 50–75 часов). 52 темы, 1015 единиц: 211 слов и сочетаний в 10 тематических темах и 484 слова в 18 частотных наборах (всего 695), 17 тем грамматики (69 правил), 7 тем фраз на слух (251 фраза). Темы в `course.json` чередуются: слова, грамматика, фразы — новое берётся подряд в порядке курса.
- Грамматика сверена с English Grammar Profile (Cambridge, уровни B1–B2, 576 описаний; O'Keeffe & Mark 2017). Добавлены пропуски B1: 3-й тип условных и wish, догадки и прошедшее у модальных, used to и would, глагол + to/-ing, сравнения, связки. EGP описывает, что ученики уровня употребляют правильно, а не обязательную программу. По условиям Cambridge материалы нельзя продвигать как «English Profile informed»; пишем «сверено с EGP». Не вошли: Future Continuous и Perfect, Past Perfect Continuous, вопросы-хвостики, артикли в обобщениях, количество (few/little, either/neither), have something done.
- Частотные наборы `freq-<ранг>.json` — слова NGSL с рангами 1001–2809, по сотне рангов в наборе (последний 2701–2809), 22–31 слово. Ученик B1 знает почти всю первую тысячу, пробелы — выше. Отобраны знаменательные слова, полезные взрослому; пропущены служебные, совсем базовые, дубли тематических тем и слова о войне и политике. Слова набора темой не связаны (такие наборы учатся не хуже тематических, Tinkham 1997). Наборы стоят через каждые две темы курса, по возрастанию ранга (М8). Знакомые полосы тест уровня отмечает сам.
- Темы слов — ситуации (деньги, поездки, техника, люди, чувства, здоровье, сочетания с предлогами) со смесью частей речи, а не наборы однотипных слов (Tinkham 1997). Сочетания с предлогами (`depend on`) — `kind: phrase` с id `c-…`, без `rank`.
- Загрузчик отказывается грузить битый контент; `ContentTest` проверяет настоящий курс и строит упражнение на каждой ступени.
- Тексты для чтения (М11) — `content/en/texts.json`: отрывки из Simple English Wikipedia (CC BY-SA 4.0) и книг Project Gutenberg (общественное достояние). Собирает `python3 -I scripts/collect_texts.py` (нужен интернет): берёт связную прозу, где ≥95% слов из NGSL 1–2000, дней/месяцев/числительных, слов курса или имён, и не больше 3 новых. В `rare` — слова вне этого словаря; в приложении слово из `rare` знакомо, когда ученик держит его в курсе. Источник и лицензию каждого текста показывать обязательно. `ContentTest.realTextsAreCreditedAndReadable` проверяет. Карточка чтения появляется только когда вся грамматика курса (темы из одних правил) держится в памяти — решение автора курса.

## Фразы на слух (М24)
- Источник — Tatoeba: английские предложения с записью носителя языка под CC BY 4.0 или CC BY-SA 4.0 и русским переводом (CC BY 2.0 FR). 98% английских записей Tatoeba (автор CK) — CC BY-NC-ND: не берём, это несвободная лицензия. Фильмы не берём: авторское право.
- Отбор вручную — `sources/tatoeba/phrases.json` (темы, id предложений, правки переводов `translations`, слово для пропуска `gaps`). Сборка: `python3 -I scripts/collect_phrases.py` (нужен ffmpeg; выгрузки Tatoeba ~50 МБ качаются в `build/tatoeba`). Пишет `content/en/topics/phrases-*.json` и `content/en/audio/ph-<id>.m4a` (моно AAC 40 кбит/с, тишина обрезана, громкость выровнена). Пропуск по умолчанию — самое редкое по NGSL слово фразы.
- В `ItemFile.audio` — файл, автор, лицензия, ссылка; приложение показывает автора и лицензию при первой встрече. `ContentTest.recordedPhrasesAreCreditedAndStudiedByEar` проверяет файлы, лицензии и упражнения.
- Лестница на слух (`ExerciseFactory`): Recognize — смысл по звуку (текста нет), FillGap — поймать слово, Translate — диктант, Speak — сказать по смыслу и сравнить с голосом. `Exercise.byEar` — звук и есть вопрос; `Exercise.recording` — играть запись вместо синтеза. После верного ответа на слух — `Screen.Heard`: текст, повтор записи, «повторите за диктором». У ответов на слух своя медиана скорости (`-ear`, М13): запись идёт до ответа.
- Воспроизведение: `Speaker.play(bytes)` — Android `MediaPlayer` из байтов, iOS `AVAudioPlayer` (не запускалось).

## ИИ на устройстве
- Платформа реализует только `OnDeviceModel` (состояние, скачивание, `generate`): Android — `GeminiNanoModel` (ML Kit Prompt API) в `shared/androidMain`; iOS — Apple Foundation Models на Swift, передаётся в `MainViewController(model)` (ещё не написано, нужен Xcode).
- Промпт и разбор ответа общие (`FreeAnswerJudge`): модель говорит только CORRECT/WRONG и даёт исправление с минимальными правками. Ответ не по формату или переписанная фраза (больше 40% слов) отбрасываются → самопроверка. Объяснение берётся из `note` курса, не от модели.
- Сначала тест, потом доверие (М21): модель проверяет ответы на занятиях только после того, как на `content/eval/free-answers.json` совпала с эталоном ≥ 90%. Результат хранится в `SavedState.aiCheck`. В журнале ответов поле `checkedBy`: code / self / ai / ai-disputed / placement.
- Gemini Nano нет в эмуляторе — там видно только состояние «недоступна»; проверять на поддерживаемом телефоне.
- ML Kit приносит с собой Google datatransport — служебную телеметрию ML Kit, которая уходит в Google. Учитывать, когда говорим «без сервера».

## Тест уровня (М23)
- Новому ученику (нет прогресса и нет `SavedState.placement`) сначала предлагается тест: 60 слов «знаю / не знаю» из `content/en/placement.json` (6 полос NGSL по 8 слов + 12 псевдослов; собирает `python3 -I scripts/build_placement.py`, он же проверяет псевдослова по NGSL и `/usr/share/dict/words`) и по 2 вопроса на тему грамматики. Можно пропустить.
- Подсчёт в `Placement`: доля «знаю» в полосе с поправкой (h − f)/(1 − f); слово курса, о котором спросили, — по ответу (если ложных «знаю» ≤ 25%), остальные — по полосе (≥ 85%); слова вне NGSL не отмечаются. Знакомое заводится в память оценкой Good и приходит на проверку через ~2 дня.

## Напоминания и уверенность
- Напоминания (М19, М20) без настроек: `StudyController` ставит одно — на ближайший день, где есть повторы или новое, в обычное время начала занятий (медиана последних; до первого — 19:00 из `StudyConfig`). Платформа реализует `ReminderScheduler`: Android — `AndroidReminders` (WorkManager, разрешение спрашивается после первого законченного занятия), iOS — `IosReminders` (ещё не запускалось).
- Проверить уведомление в эмуляторе: `adb shell cmd jobscheduler run -f -n androidx.work.systemjobscheduler com.jatta.app 1`.
- Уверенность (М13) — по скорости ответа, без тапа: быстрая ошибка — уверенная, подсказка к ней помечается (`Grading.isConfidentError`).
- Озвучка — синтез речи платформы (`Speaker`: Android `AndroidSpeaker` = TextToSpeech, en-US; iOS `IosSpeaker` = AVSpeechSynthesizer, не запускалось). Звучит только английский из `Exercise.listen` и примеры. Слово звучит само при показе и в вопросе «что значит», ответ — после ответа; до ответа звук не должен подсказывать решение. В эмуляторе с `-no-audio` синтез идёт, но звука нет.

## Лимит нового (М18)
- 12 новых в день — на день, а не на занятие: `ItemProgress.firstDay` — день первого изучения, план дня вычитает начатое сегодня. Знакомое по тесту уровня заводится `Engine.placeKnown` с `firstDay = null` и в лимит не идёт.
- Старые состояния (`SavedState.firstDaysRecorded = false`) один раз берут дни первого изучения из журнала (`LogReplay.firstStudyDays`).

## Калибровка и подгонка памяти (М2)
- Отдельной контрольной нет: каждый плановый повтор проверяет прогноз модели. `Calibration.of` проигрывает журнал `answers.jsonl` через FSRS: перед повтором известна вероятность вспомнить, после — вспомнили ли. Считаются только первые ответы дня (`grade != null`) по уже встреченным единицам.
- Итог: средний прогноз против доли вспомненного с 95% интервалом Вильсона и разбивкой по уровням прогноза; вывод — от `StudyConfig.minReviewsForCalibration` (30) повторов. Экран `Screen.Calibration`, ссылка «Точность прогноза памяти» на главной.
- Знакомое по тесту уровня пишется в журнал с `checkedBy = placement`: проигрывание восстанавливает ту же память, но эти записи не оцениваются. У тех, кто прошёл тест до этого, таких записей нет — их первый повтор просто считается первой встречей.
- Подгонка параметров: `engine/fsrs/FsrsOptimizer.kt` — порт оптимизатора py-fsrs 6.3.2 (log loss на повторах со второго дня, Adam 5 эпох, пачки по 512, шаг 0.04 с косинусным затуханием, обрезка по границам `Fsrs.LOWER_BOUNDS/UPPER_BOUNDS`, первые 64 повтора единицы, меньше 512 повторов — не подгоняет). Отличия: градиент — центральные разности вместо autograd, пачка — целые единицы. Ошибка сверена с py-fsrs до 1e-12 (`FsrsOptimizerVectors`); на одних данных наша подгонка и py-fsrs дают почти одно и то же (ошибка на новых повторах 0.4060 и 0.4055 при стандартных 0.4106).
- Решение принять — `study/calibration/PersonalFit.kt`: последние 20% повторов (по дням) откладываются, подгонка идёт на остальных, обе модели оцениваются на отложенных; лучше прежней — подгоняется заново по всем и принимается (`SavedState.fsrsParameters`, итог в `fsrsFit`). Первая попытка — с 640 повторов (512 + отложенные), дальше каждые 512 новых (`StudyConfig`).
- Запуск — в конце занятия, в фоне (`background` у `StudyController`). Принятые параметры пересобирают память всех единиц из журнала (`LogReplay.progress`), так что сроки повторов идут уже по новой модели. Единицы, начатые с теста уровня, в подгонку не идут: их история начинается с догадки, а не с первой встречи.
- Экран «Точность прогноза» показывает, чьи параметры в работе и как прошла последняя проверка на отложенных повторах.

## Правила
- Что, когда и сколько учить, решает только код движка. ИИ только проверяет свободные ответы; без модели свободный ответ ученик сверяет с образцом сам.
- Числа механик живут в `EngineConfig`, числа хода занятия — в `StudyConfig`. У каждого числа метка механики и уровень доказательности.
- У каждой механики свой тест. Новая механика: правило в docs, параметр в конфиге, код, тест.
- FSRS — порт py-fsrs 6.3.2. При изменении формул перегенерировать векторы: `scripts/fsrs_vectors.py` (Python 3.10+, `pip install fsrs==6.3.2`) и `scripts/fsrs_optimizer_vectors.py` (`pip install 'fsrs[optimizer]==6.3.2'`, тянет torch).
- Простой код: без DI-фреймворков, данные и функции вместо иерархий классов.

## Команды
```bash
export JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home
./gradlew :engine:jvmTest :study:jvmTest
./gradlew :androidApp:assembleDebug
./gradlew :androidApp:assembleRelease
./gradlew :shared:compileKotlinIosSimulatorArm64
```
Релиз: `assembleRelease` — R8 со сжатием, подпись отладочным ключом (ставится из файла, как Drop Tuner). ML Kit создаёт свои компоненты через рефлексию — в `androidApp/proguard-rules.pro` он сохранён целиком; без этого Gemini Nano молча ломается, а на эмуляторе этого не видно. Релизная сборка не отладочная: `run-as` в её данные не пускает. В GitHub-релиз кладём `Jatta.apk`, тег `vX.Y`, описание на русском.
Эмулятор: `$SDK/emulator/emulator -avd droptuner -no-audio` (SDK в `/opt/homebrew/share/android-commandlinetools`), затем `adb install -r androidApp/build/outputs/apk/debug/androidApp-debug.apk`.

## Окружение
- JDK 17 из Homebrew, системной Java нет. `local.properties` указывает на Android SDK.
- Версии: Kotlin 2.4.20, Gradle 9.7.1, AGP 9.1.1, Compose Multiplatform 1.12.1, compileSdk 37.
- Xcode не установлен: iOS-код компилируется, но для симулятора, сборки приложения и Foundation Models нужен Xcode.
- Gemini Nano работает только на поддерживаемых телефонах, не в эмуляторе.

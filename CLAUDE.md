# Jatta

Jatta (каз. «заучивай») — ИИ-учебник английского на Kotlin Multiplatform (Android + iOS), без сервера.
Научная основа и механики М1–М28: `docs/mechanics.html` (опубликовано: https://claude.ai/artifact/1rr8HKEgen5H7N3BP9XS3j).

Лицензия: GPL-3.0-or-later (`LICENSE`) с дополнительным разрешением по пункту 7 GPL на связывание с Google ML Kit. Текст разрешения и чужой код/данные — в `THIRD_PARTY_NOTICES.md`: при заимствовании кода или данных добавлять туда источник и лицензию. Новую закрытую библиотеку без отдельного разрешения не подключать.

## Модули
- `engine` — чистое ядро: FSRS, план дня, очередь занятия, лестница, отдых. Без часов, базы, сети и платформенных API.
- `study` — всё вокруг движка без UI: формат и загрузка контента, упражнения, проверка ответов, хранение прогресса (`LearnerStore`, JSON + журнал `answers.jsonl`), ход занятия (`StudyController` → `Screen`), проверка свободных ответов моделью (`judge/`).
- `shared` — интерфейс на Compose Multiplatform. Только рисует `Screen` и вызывает `StudyController`. Оформление — `Theme.kt`: киберпанк в двух палитрах — тёмная (неон на почти чёрном) и светлая (те же оттенки темнее, чтобы читались на белом); скошенные углы, сетка, компоненты `NeonButton`, `Panel`, `Label`, `NeonBar`. Цвета брать только через `Neon.*` (текущая палитра), не литералами. Выбор темы — `ThemeChoice` (система / светлая / тёмная) в `SavedState`, переключатель на главной; Android подстраивает иконки системных панелей через `onDarkTheme`. Шрифты Exo 2 и JetBrains Mono (OFL, с кириллицей) в `src/commonMain/composeResources/font/`; эта папка склеивается с `content/` задачей `syncResources`.
- Системное «назад» (жест или кнопка Android) — `StudyController.goBack()` через `NavigationBackHandler` (navigationevent-compose) в `ScreenFlow.kt`: из занятия — как «Закончить», из теста уровня — к его началу, из итогов дня — как «Поехали», из остального — на главную. На главной и в начале теста жест не перехватывается и закрывает приложение; какие экраны корневые — `Screen.canGoBack`.
- Индикаторы: на главной «Память» = сколько единиц держится в памяти (вспомнятся завтра с вероятностью ≥ 85%), а не «пройдено»; у тем — то же по теме; в занятии — шаги (`Steps`), полоса только растёт.
- `androidApp` — `MainActivity`. iOS: `MainViewController()` в `shared/iosMain`, Xcode-проект появится после установки Xcode.
- Манифест: `configChanges` с `orientation|screenSize|…|uiMode` — занятие переживает поворот и смену темы; `<queries>` с `TTS_SERVICE` — Android 11+ иначе не видит движок синтеза речи; `INTERNET` — только для загрузки модели; `FOREGROUND_SERVICE_DATA_SYNC` и `SystemForegroundService` с `dataSync` — загрузка модели в фоне; `uses-native-library` `libOpenCL.so` и `libvndksupport.so` — Gemma на видеокарте, где она есть; `RECORD_AUDIO` и `<queries>` с `RecognitionService` — ответ голосом на ступени «Вслух».

## Контент
- Источник — `content/en/`: `course.json` (темы по порядку) и `topics/<id>.json`. В приложение он копируется задачей `syncContent` модуля `shared`.
- Слово: `en`, `ru`, `note`, `examples` с `gap`. Правило: `ru` — правило одной строкой, `note` — объяснение, у примеров есть `gap`, `cue` и `wrong` (неверные варианты для выбора).
- `rank` (М8) — ранг слова в NGSL 1.2 (`sources/ngsl/`, CC BY-SA 4.0, в приложение не попадает). Слова нет в NGSL — `rank` не ставим. `ContentTest.wordRanksComeFromNgsl` это проверяет.
- Курс — объём учебника уровня Intermediate (English File Intermediate: 20 уроков, ~20 тем грамматики, ~20 тем слов, 50–75 часов). 68 тем, 1268 единиц: 436 слов и сочетаний в 19 тематических темах и 484 слова в 18 частотных наборах, 24 темы грамматики (97 правил), 7 тем фраз на слух (251 фраза). Темы в `course.json` чередуются: слова, грамматика, фразы — новое берётся подряд в порядке курса. Вторая половина (еда, дом и город, учёба, покупки, природа, кино и книги, спорт, семья, фразовые глаголы; Present Simple/Continuous, can/could/be able to, -ed/-ing и наречия, местоимения и so/neither, get used to/would rather/had better, zero conditional/unless/in case, вопросы) стоит в конце курса. Проверка темы без Gradle: `python3 -I scripts/check_topic.py тема.json` (те же правила, что в `ContentLoader` и `ContentTest`, плюс ранги NGSL; `--ranks слово…` печатает ранги). Формат для авторов тем — `docs/course-format.md`.
- Грамматика сверена с English Grammar Profile (Cambridge, уровни B1–B2, 576 описаний; O'Keeffe & Mark 2017). Добавлены пропуски B1: 3-й тип условных и wish, догадки и прошедшее у модальных, used to и would, глагол + to/-ing, сравнения, связки. EGP описывает, что ученики уровня употребляют правильно, а не обязательную программу. По условиям Cambridge материалы нельзя продвигать как «English Profile informed»; пишем «сверено с EGP». Не вошли: Future Continuous и Perfect, Past Perfect Continuous, вопросы-хвостики, артикли в обобщениях, количество (few/little, either/neither), have something done.
- Частотные наборы `freq-<ранг>.json` — слова NGSL с рангами 1001–2809, по сотне рангов в наборе (последний 2701–2809), 22–31 слово. Ученик B1 знает почти всю первую тысячу, пробелы — выше. Отобраны знаменательные слова, полезные взрослому; пропущены служебные, совсем базовые, дубли тематических тем и слова о войне и политике. Слова набора темой не связаны (такие наборы учатся не хуже тематических, Tinkham 1997). Наборы стоят через каждые две темы курса, по возрастанию ранга (М8). Знакомые полосы тест уровня отмечает сам.
- Темы слов — ситуации (деньги, поездки, техника, люди, чувства, здоровье, сочетания с предлогами) со смесью частей речи, а не наборы однотипных слов (Tinkham 1997). Сочетания с предлогами (`depend on`) — `kind: phrase` с id `c-…`, без `rank`.
- Загрузчик отказывается грузить битый контент; `ContentTest` проверяет настоящий курс и строит упражнение на каждой ступени.
- Список форм первой тысячи NGSL — `content/en/basic-words.json` (собирает `python3 -I scripts/build_basic_words.py`, CC BY-SA 4.0, в `THIRD_PARTY_NOTICES.md`): в приложении это «знакомые слова» при разборе своего текста.
- Тексты для чтения (М11) — `content/en/texts.json`: отрывки из Simple English Wikipedia (CC BY-SA 4.0) и книг Project Gutenberg (общественное достояние). Собирает `python3 -I scripts/collect_texts.py` (нужен интернет): берёт связную прозу, где ≥95% слов из NGSL 1–2000, дней/месяцев/числительных, слов курса или имён, и не больше 3 новых. В `rare` — слова вне этого словаря; в приложении слово из `rare` знакомо, когда ученик держит его в курсе. Источник и лицензию каждого текста показывать обязательно. `ContentTest.realTextsAreCreditedAndReadable` проверяет. Карточка чтения появляется только когда вся грамматика курса (темы из одних правил) держится в памяти — решение автора курса.
- Предложения для перевода (М25) — `content/en/sentences.json`: 1928 пар Tatoeba для 681 слова курса, подробности в разделе «Перевод фраз».

## Фразы на слух (М24)
- Источник — Tatoeba: английские предложения с записью носителя языка под CC BY 4.0 или CC BY-SA 4.0 и русским переводом (CC BY 2.0 FR). 98% английских записей Tatoeba (автор CK) — CC BY-NC-ND: не берём, это несвободная лицензия. Фильмы не берём: авторское право.
- Отбор вручную — `sources/tatoeba/phrases.json` (темы, id предложений, правки переводов `translations`, слово для пропуска `gaps`). Сборка: `python3 -I scripts/collect_phrases.py` (нужен ffmpeg; выгрузки Tatoeba ~50 МБ качаются в `build/tatoeba`). Пишет `content/en/topics/phrases-*.json` и `content/en/audio/ph-<id>.m4a` (моно AAC 40 кбит/с, тишина обрезана, громкость выровнена). Пропуск по умолчанию — самое редкое по NGSL слово фразы.
- В `ItemFile.audio` — файл, автор, лицензия, ссылка; приложение показывает автора и лицензию при первой встрече. `ContentTest.recordedPhrasesAreCreditedAndStudiedByEar` проверяет файлы, лицензии и упражнения.
- Лестница на слух (`ExerciseFactory`): Recognize — смысл по звуку (текста нет), FillGap — поймать слово, Translate — диктант, Speak — сказать по смыслу и сравнить с голосом. `Exercise.byEar` — звук и есть вопрос; `Exercise.recording` — играть запись вместо синтеза. После верного ответа на слух — `Screen.Heard`: текст, повтор записи, «повторите за диктором». У ответов на слух своя медиана скорости (`-ear`, М13): запись идёт до ответа.
- Воспроизведение: `Speaker.play(bytes)` — Android `MediaPlayer` из байтов, iOS `AVAudioPlayer` (не запускалось).

## Ступень «Вслух» (распознавание речи)
- На верхней ступени (`Exercise.Speak`) ответ говорят в микрофон. Платформа реализует `SpeechInput` (`shared`): Android — `AndroidSpeechInput`, только распознавание на самом телефоне (`SpeechRecognizer.createOnDeviceSpeechRecognizer`, Android 12+): голос не уходит в сеть. iOS пока передаёт null. Нет распознавания на устройстве — прежняя самопроверка «Сказал(а), показать ответ»; она же доступна ссылкой «Без микрофона».
- Разрешение на микрофон спрашивается при первом нажатии (`MainActivity.askMicrophone`). Нет английского пакета распознавания — система сама предлагает его скачать (~60 МБ, `triggerModelDownload`, Android 13+), приложение просит нажать на микрофон после загрузки.
- Проверка (`SpokenAnswer`): засчитано, если хоть один из вариантов распознавания (до 5) после `AnswerCheck.normalize` совпал с образцом; числа 0–999 приводятся к словам («30» = «thirty»). В журнал — `checkedBy = speech`. Иначе — самопроверка: видно, что расслышал телефон (ближайший к образцу вариант по chrF), и разница с образцом; решает ученик (`self`), потому что распознавание само ошибается. Совпадение строгое, как в уроках: порог перевода М25 здесь не действует.
- Эмулятор запущен с `-no-audio`: микрофон молчит, само распознавание проверяется на телефоне. Путь с распознанным текстом — в `SpokenAnswerTest` и `StudyControllerTest`.

## Перевод фраз (М25)
- В конце занятия — до 4 предложений на перевод с русского на английский (`StudyConfig.translationsPerSession`). Русские ответы не проверяем: модели на телефоне судят о русском хуже (решение автора курса). Сессия, оборванная усталостью, перевод пропускает.
- Источник — `content/en/sentences.json` (Tatoeba, CC BY 2.0 FR): `ru[0]` — задание, `en` — английские переводы именно этого русского предложения (эталоны), `items` — слова курса. Остальные `ru` в приложении не используются. Собирает `python3 -I scripts/collect_sentences.py` из выгрузок `build/tatoeba` (их качает `collect_phrases.py`): хотя бы одно слово курса, остальные из NGSL 1–1000 или Tom/Mary, 4–10 слов, до 3 предложений на слово, сначала с большим числом переводов. Вычитанные и отброшенные (неверный перевод или альтернатива, идиома, архаика, сленг, тема) — `skip` в `sources/tatoeba/sentences.json`; после пересборки новые пары тоже вычитывать.
- Подбор (`TranslationPicker`): все слова предложения держатся в памяти; сначала самые слабые; слово не повторяется в одном занятии; переведённое верно больше не даётся, ошибка — через `translationRetryDays`.
- Перевод в любое время: карточка «Перевод фраз» на главной → `StudyController.startTranslation` → те же `Screen.Translate`/`Translated` с `practice = true` (в шапке счётчик без полосы, «Закончить» возвращает на главную с итогом). `TranslationPicker.practice` даёт все открытые фразы без лимита: сначала те, где все слова курса уже встречены (самые слабые первыми), потом остальные по возрастанию ранга NGSL; когда открытых не осталось — заново все. Проверка и журнал те же, что в конце занятия; памяти и сроков не касается.
- Проверка, мягкое правило автора курса: неверно только явно неверное — другой смысл (другое действие, вещь, качество или человек, перепутано кто кого, наоборот, лишнее или пропущенное «не», потерян главный смысл) или непонятно. Грамматические ошибки, опечатки и другие слова при том же смысле — верно; отличия подсвечиваются против ближайшего перевода человека.
  1. Код (`TranslationScore`, `Chrf`): chrF++ (Popović 2017; символы 1–6 и слова 1–2, β = 2) после `AnswerCheck.normalize` против всех эталонов; ≥ 0,8 с тем же числом отрицаний — засчитано.
  2. Ниже — модель, если прошла свой тест на переводах: `FreeAnswerJudge.judgeTranslation` спрашивает только «MEANING: SAME / DIFFERENT», без исправлений (с просьбой исправить маленькие модели отклоняли любую грамматическую ошибку). Иначе — самопроверка по тому же правилу.
- Доверие к модели отдельное (М21): `testModel` гоняет и `content/eval/free-answers.json` (уроки, строгое правило), и переводы из `content/eval/translations.json`, которые порог оставляет модели; `AiCheck.translationsEnabled` — от 90% на них. В уроках проверка прежняя, строгая: там упражнение и есть грамматика.
- `content/eval/translations.json` — 92 перевода с разметкой по мягкому правилу (61 верный, 31 явно неверный). `TranslationEvalTest`: порог засчитывает 24, из них 3 явно неверных (he вместо she, him вместо her, boring вместо bored — n-граммы этого не видят); верных засчитывает 21 из 61, остальные решают модель или ученик.
- Перевод не меняет память и сроки: он пишется в `translations.jsonl` (`TranslationEntry`), а не в `answers.jsonl`, на котором калибруется и подгоняется FSRS.
- `WordDiff` сравнивает слова после раскрытия сокращений («does not» = «doesn't»); у совпавших частей `written` — как написал ученик.

## ИИ на устройстве
- Платформа реализует только `OnDeviceModel` (имя, размер загрузки, состояние, скачивание, `generate`). Android — `PhoneModel` в `shared/androidMain`: `GeminiNanoModel` (ML Kit Prompt API, системная служба AICore), где телефон её поддерживает, иначе `GemmaModel` — Gemma 4 E2B внутри приложения на LiteRT-LM (`com.google.ai.edge.litertlm`, Apache 2.0). На поддерживаемых телефонах Gemini Nano — та же Gemma 4. iOS — Apple Foundation Models на Swift, передаётся в `MainViewController(model)` (ещё не написано, нужен Xcode).
- `GemmaModel`: файл `gemma-4-E2B-it.litertlm` (2 588 147 712 байт) с Hugging Face `litert-community/gemma-4-E2B-it-litert-lm`, ревизия и SHA-256 закреплены в коде. Качает `ModelFile` (`study/jvmMain`, работает и на Android) внутри `ModelDownloadWorker` — фоновая работа WorkManager с уведомлением о прогрессе и кнопкой «Отменить» (foreground service типа dataSync): идёт и когда приложение свёрнуто или закрыто, ждёт сеть, обрыв докачивается с того же места (Range), в конце сверяются размер и SHA-256, потом уведомление «Модель скачана». Открытое приложение подхватывает идущую загрузку (`ModelState.Downloading` → `followDownload`).
- Запуск движка: впервые — на тесте точности (не при открытии приложения), дальше — сразу при открытии, бэкендом, который уже сработал. GPU может загрузиться и упасть на первом же вопросе (нет OpenCL) — поэтому после загрузки пробный вопрос в 1 токен. Нативная библиотека может и уронить приложение (на эмуляторе на Mac M5 CPU-бэкенд даёт SIGILL): перед попыткой пишется `models/failed-<GPU|CPU>`, снимается только после успеха. Бэкенд с такой отметкой больше не пробуется; если отмечены оба — модель «недоступна». Сбросить — очистить данные приложения. Нужны 64-битный ARM (LiteRT-LM собран только под arm64-v8a и x86_64) и от ~5,5 ГБ памяти по `totalMem`, иначе «недоступна». Движок грузится в фоне, как только файл есть (~10 с), сначала GPU (OpenCL, `uses-native-library` в манифесте), потом CPU. Настройки как у Gemini Nano: top-k 1, температура 0, 80 токенов. Классы LiteRT-LM целиком сохранены в `proguard-rules.pro`: своих правил у библиотеки нет, а натив зовёт их по именам.
- APK собирается только под ARM (`abiFilters` arm64-v8a и armeabi-v7a, на 32-битных телефонах без Gemma), натив сжат (`useLegacyPackaging`): релиз ~17 МБ вместо 6 МБ.
- Промпт и разбор ответа общие (`FreeAnswerJudge`): модель говорит только CORRECT/WRONG и даёт исправление с минимальными правками. Ответ не по формату или переписанная фраза (больше 40% слов) отбрасываются → самопроверка. Объяснение берётся из `note` курса, не от модели.
- Сначала тест, потом доверие (М21): модель проверяет ответы на занятиях только после того, как на `content/eval/free-answers.json` совпала с эталоном ≥ 90%. Результат хранится в `SavedState.aiCheck`. В журнале ответов поле `checkedBy`: code / speech / self / ai / ai-disputed / placement.
- Gemini Nano нет в эмуляторе, поэтому там выбирается Gemma. Эмулятор `droptuner` (2 ГБ) ей мал — для проверки Gemma есть AVD `jatta-gemma` (6 ГБ, тот же образ android-35 arm64). Чтобы не качать 2,6 ГБ заново, файл (или его начало как `.part`) можно положить в `files/models/` отладочной сборки через `adb push` и `run-as`. Ответы Gemma на этом эмуляторе не проверить: OpenCL нет, CPU-бэкенд падает с SIGILL (эмулятор на M5 объявляет SME, которого не даёт). Точность файла телефона меряется на Mac через `LocalModelEvalTest -PlitertModel=...`.
- Локальные модели меряются на Mac тем же кодом проверки (`LocalModelEvalTest`, настройки как у Gemini Nano: temperature 0, top-k 1, 80 токенов): через Ollama — `./gradlew :study:jvmTest --tests '*LocalModelEvalTest*' --rerun -PollamaModel=gemma4:e2b`; файл телефона через LiteRT-LM для JVM — `... -PlitertModel=build/models/gemma-4-E2B-it.litertlm`. Отчёт печатается и пишется в `$TMPDIR/jatta-model-<модель>.txt`; без свойств тест ничего не делает.
- Gemma 4 E4B (27.10.2026, Ollama, 6,6 ГБ; файл для телефона 3,7 ГБ): уроки 95,8%, разбор чата 23 из 24 — как E2B; переводы 85,2% (длинная подсказка — 89,7%) — ниже порога; собеседник чуть разговорчивее, но не принципиально. Тяжелее на 1,1 ГБ и медленнее — остаёмся на E2B.
- Замер 27.10.2026 (Mac M5, Ollama 0.32.1): Gemma 4 E2B (4,6 ГБ в Ollama, Apache 2.0) — уроки 95,8%, переводы 91,1% без единого засчитанного явно неверного, 0,45 с на ответ: проходит оба порога. Qwen3.5 4B — 87,5% и 72%; Qwen3.5 0.8B — 54% (почти на всё отвечает «верно»); Qwen3.5 9B (не для телефона) — уроки 95,8%. На телефоне Gemma 4 идёт через LiteRT-LM — его квантовку надо будет перемерить.
- ML Kit приносит с собой Google datatransport — служебную телеметрию ML Kit, которая уходит в Google. Учитывать, когда говорим «без сервера».

## Тест уровня (М23)
- Новый ученик начинает с главной и первого занятия без теста и без модели: карточка «Уже знаете английский?» на главной (`Home.placementOffered`, пока нет `SavedState.placement`) ведёт на `Screen.PlacementIntro`, «Начну с начала» убирает её насовсем. Разделы «Проверка свободных ответов», «Разговор с ИИ» и «Свой текст» появляются на главной после первого занятия (`progress.met > 0`), чтобы новичок не начинал с загрузки 2,6 ГБ. Тест после занятий не трогает уже начатые единицы. Тест: 60 слов «знаю / не знаю» из `content/en/placement.json` (6 полос NGSL по 8 слов + 12 псевдослов; собирает `python3 -I scripts/build_placement.py`, он же проверяет псевдослова по NGSL и `/usr/share/dict/words`) и по 2 вопроса на тему грамматики. Можно пропустить.
- Подсчёт в `Placement`: доля «знаю» в полосе с поправкой (h − f)/(1 − f); слово курса, о котором спросили, — по ответу (если ложных «знаю» ≤ 25%), остальные — по полосе (≥ 85%); слова вне NGSL не отмечаются. Знакомое заводится в память оценкой Good и приходит на проверку через ~2 дня.

## Свой текст и свои темы
- «Свой текст» на главной → `Screen.OwnText` (поле ввода) → `StudyController.analyzeText` → `Screen.TextStudy`: `TextAnalyzer` ищет в тексте слова и сочетания курса (формы из `en`, `also`, `gap`; записанные фразы Tatoeba не считаются — это предложения, а не словарь; сочетания ищутся целиком), делит их на держащиеся, встреченные и новые, считает долю знакомых слов (первая тысяча NGSL из `basic-words.json` + держащиеся слова курса + имена с заглавной не в начале предложения) и перечисляет слова вне курса и первой тысячи. «Учить слова текста» → `Engine.planItems` (`DayPlanner.items`): все встреченные слова текста как повторы, самые забытые первыми (как в теме по выбору, М26), новые — в пределах дневного лимита. Текст не сохраняется. Перевод слов вне курса моделью не делается (решение: маленькие модели переводят на русский ненадёжно).
- Своя тема: кнопка «Тема из файла» в разделе «Данные» → `StudyController.addTopic` проверяет файл (`ContentLoader.checkCustom`: формат, уникальные id темы и единиц, известные `requires`, без записей) → `CustomTopicStore` кладёт его в `files/topics/<id>.json` → `App` пересоздаёт контроллер (`generation`). `ContentLoader.load(..., customTexts)` добавляет такие темы в конец курса (`StudyCourse.customTopics`, на главной подпись «своя»). Битый файл в папке молча пропускается при старте. Прогресс по единицам, которых нет в курсе (тема удалена, импорт с другого телефона), при загрузке отбрасывается (`Learner.known()`), журнал остаётся.
- Данные: «Сохранить» / «Загрузить» на главной — `ProgressBundle` (JSON: `SavedState`, `answers.jsonl`, `translations.jsonl`), `LearnerStore.export/import`, файл через системный диалог (`FileExchange`, Android — `AndroidFiles` с `CreateDocument`/`OpenDocument`). После загрузки контроллер перечитывает состояние и показывает `Home.notice` до следующего возврата на главную.
- Виджет Android «Jatta: сегодня» (`TodayWidget`, `shared/androidMain`): повторить · новое. Считает план дня в `TodayWidgetWorker` (WorkManager) из курса и `learner.json`; обновляется при сворачивании приложения (`MainActivity.onStop`) и раз в 6 часов. Без прогресса показывает «—».
- Оформление: `Look` (неон / спокойно) в `SavedState.look`, переключатель рядом с темой. Спокойная палитра — `CalmDark`/`CalmLight` в `Theme.kt`: приглушённые синий, роза и золото, без сетки и свечения, скосы те же.

## Напоминания и уверенность
- Напоминания (М19, М20) без настроек: `StudyController` ставит одно — на ближайший день, где есть повторы или новое, в обычное время начала занятий (медиана последних; до первого — 19:00 из `StudyConfig`). Платформа реализует `ReminderScheduler`: Android — `AndroidReminders` (WorkManager, разрешение спрашивается после первого законченного занятия), iOS — `IosReminders` (ещё не запускалось).
- Проверить уведомление в эмуляторе: `adb shell cmd jobscheduler run -f -n androidx.work.systemjobscheduler com.jatta.app 1`.
- Уверенность (М13) — по скорости ответа, без тапа: быстрая ошибка — уверенная, подсказка к ней помечается (`Grading.isConfidentError`).
- Озвучка — синтез речи платформы (`Speaker`: Android `AndroidSpeaker` = TextToSpeech, en-US; iOS `IosSpeaker` = AVSpeechSynthesizer, не запускалось). Звучит только английский из `Exercise.listen` и примеры. Слово звучит само при показе и в вопросе «что значит», ответ — после ответа; до ответа звук не должен подсказывать решение. В эмуляторе с `-no-audio` синтез идёт, но звука нет.

## Разговор с ИИ (М28)
- На главной карточка «Разговор с ИИ» → `Screen.ChatTopics` (темы из `content/en/chat.json`: id, название, тема для модели по-английски) → `Screen.Chat`. Открывается, когда модель готова и ученик провёл хотя бы одно занятие. Пока модель не прошла проверку точности уроков (М21, `trustedJudge`), разбор ошибок помечен как приблизительный (`reviewTrusted` в `ChatTopics` и `Chat`, подпись «Разбор · приблизительно»); после проверки пометка исчезает. На телефоне без модели карточки нет.
- Ход разговора — `chat/ChatFlow`: на каждую фразу ученика сначала разбор (`FreeAnswerJudge.reviewChat` — формат VERDICT/FIXED, как в уроках, и тот же запрет переписывания >40% слов), потом ответ собеседника. Правка только в знаках препинания — не ошибка. Разбор под фразой: замены «go → went», вставки «+ the», лишнее «− to» (`changesOf` по `WordDiff`) и исправленная фраза, собранная из слов самого ученика (модель отвечает строчными). Объяснений от модели нет — как и в уроках.
- Собеседник (`ChatPartner`) — настоящий чат, а не стенограмма в одной подсказке: `OnDeviceModel.chat(system, turns)` с характером в системной инструкции (Alex, медсестра из Манчестера, велосипед, готовка, старые фильмы) и репликами как ходами user/model; первый ход ученика — скрытое «Hi!». Выборка живая (температура 0,8, top-k 64, top-p 0,95), у проверки ответов — 0. Gemma на LiteRT-LM получает систему и историю родными средствами (`ConversationConfig.systemInstruction`, `initialMessages`), Gemini Nano — склеенную стенограмму (`transcript`). Эмодзи, звёздочки и переносы вычищает код (`ChatPartner.tidy`), а не подсказка. Слова курса в подсказку не передаются (маленькая модель вставляла их невпопад); встреченные слова курса просто подсвечиваются в репликах.
- Последние `chatTurnsKept` реплик идут в историю. Нет ответа за `chatTimeoutMs` — «Модель не ответила», можно написать ещё раз.
- Ввод — текст или диктовка тем же `SpeechInput`, что на ступени «Вслух». Разговор живёт только в памяти: не пишется в журнал, не меняет память и сроки повторов, серию не продлевает.

## Подсказки для маленьких моделей
Модели на телефоне — 2–4 млрд параметров. Что работает (Apple «Prompting an on-device foundation model», Google «Prompt design for Gemini Nano», замеры ниже):
- Коротко и прямо: одна задача, команда или вопрос, без преамбул и повторов. Длинные списки правил и «never…» не помогают.
- Строгость формата — в коде, не в подсказке: разбор ответа ищет SAME/DIFFERENT где угодно, VERDICT/FIXED — с разметкой и без; мусор (эмодзи, `**`, переносы) чистит код.
- Роль и характер («You are Alex, a nurse from Manchester…») меняют поведение сильнее правил.
- Чат — родным форматом модели (система + ходы), не стенограммой «Alex:/Learner:» в одном сообщении.
- Температура: проверка — 0, разговор — ~0,8.
- Каждую правку подсказки мерить `LocalModelEvalTest` (`-PollamaModel=…` или `-PlitertModel=…`): уроки, переводы, разбор чата и три пробных разговора со статистикой. Варианты подсказок сравнивать временным тестом рядом и удалять его после решения.
- Замер 27.10.2026 на Gemma 4 E2B: короткие подсказки уроков и переводов дали ровно столько же, сколько длинные (95,8% и 91,1%); примеры в подсказке перевода не помогли (89,7%), фраза «что считать другим смыслом» — навредила (88,2%). Собеседник с характером и настоящими ходами реагирует на сказанное и рассказывает о себе; с прежней подсказкой все 15 реплик кончались вопросом, 7 начинались с «That sounds».
- Подсказка подбирается под модель: Gemma 4 E4B строже к смыслу, и ей длинная подсказка перевода с правилами помогала (89,7% против 85,2% у короткой), а E2B — нет.
- Файл телефона (`gemma-4-E2B-it.litertlm`, LiteRT-LM на Mac, `-PlitertModel=build/models/gemma-4-E2B-it.litertlm -PtestJava=<java 21+>`: библиотека собрана под Java 21) слабее той же модели в Ollama: уроки 91,6%, переводы 86,7% (ниже порога — на таком телефоне переводы сверяет ученик), разбор чата 22 из 24, 0,9 с на ответ. Прежняя длинная подсказка перевода на нём — 73,5%: короткая лучше на 13 пунктов. Разговор через `systemInstruction` и `initialMessages` работает.

## Тема по выбору (М26)
- Любую тему можно пройти отдельно: нажать на неё на главной → `Screen.Topic` (сколько повторить, сколько из них раньше срока, сколько новых сегодня, на что тема опирается) → «Пройти тему». Закрытую тоже.
- План темы — `Engine.planTopic` / `DayPlanner.topic`: все встреченные единицы темы, самые забытые первыми, хоть и не пора; новые — в пределах того, что осталось от дневного лимита (М18).
- Ранний повтор — обычный повтор: FSRS сам даёт ему меньше (при вероятности вспомнить ~99% стабильность растёт слабо) и переносит следующий повтор от сегодняшнего дня. Пример на наших параметрах: слово с интервалом 11 дней, пройденное на следующий день верно, придёт через 15 дней от этого дня (вовремя оно ушло бы на 46). Забыл — повтор завтра.
- Повтор в тот же день (тему прошли второй раз за день) меняет память по краткосрочной формуле FSRS, но в калибровку не идёт: он ничего не предсказывает про забывание; подгонка его тоже не считает.

## Словарь и содержание темы
- «Словарь →» рядом с темами на главной → `Screen.Dictionary`: все единицы курса по порядку курса, поиск по английскому (сначала те, что начинаются с запроса), по `also` и по русскому (`Dictionary.search`, `study/dictionary`). Запрос живёт в `Screen.Dictionary.query` (`searchDictionary`), чтобы возврат с карточки его не терял. У каждой единицы состояние: новое / учится / держится (`ItemStatus`: вероятность вспомнить завтра и через сколько дней повтор).
- Карточка единицы — `Screen.ItemCard` (`openItem`): перевод, `note`, примеры с озвучкой, ранг NGSL, память, ссылка на тему, автор записи у фраз на слух. Назад (`closeItem` или системное «назад») возвращает туда, откуда открыли: в словарь или в тему (`cardOrigin`).
- Экран темы (`Screen.Topic.entries`) перечисляет её содержание: слова с переводом, правила одной строкой; нажатие открывает карточку. Это и есть «учебник» темы: читать до занятия или сверяться после.

## Итоги дня и серия (М27)
- Раз в день, при первом открытии после дня, когда вы занимались, — `Screen.DailySummary`: итоги вчера (ответов, с первого раза, новых, повторов, переводов, минут) и серия. «Поехали» ставит `SavedState.lastSummaryDay`.
- Всё считается из журналов (`DailyProgress`): занимались в день — есть ответ (не от теста уровня) или перевод. Минуты — от первого до последнего ответа в каждом заходе, заход рвётся паузой больше 20 минут.
- Серия: дни подряд с занятиями, сегодня — когда уже занимались. Пропуск рвёт её, только если в тот день было что учить: день без повторов и нового — отдых (память на тот день восстанавливается из журнала, `engine.planDay`). Полоса недели: занимались / отдых / пропуск / сегодня.
- Серия — добавка вне ядра: план дня от неё не зависит, за пропуск не ругаем. Первое занятие дня продлевает серию — на экране «Готово» анимация с «+1».
- Серия на главной нажимается (и ссылка «Мой прогресс →») → `Screen.Progress`: рекорд серии, дней занятий, календарь 12 недель (ярче — дольше), график памяти по дням (`MemoryChart.kt`: «в памяти» и пунктиром «встречено», шкала слева, даты снизу, касание или ведение пальцем показывает день), разделы (слова и сочетания / грамматика / фразы на слух: в памяти, встречено, всего) и итоги за всё время. `ProgressReport.of` — один проход по журналу день за днём, в фоне.
- Анимация (`StreakScreens.kt`): неоновое кольцо заполняется, число набегает, мерцает пламя, после — искры; дни недели появляются по одному. Контроллер создаётся в фоне (`App`), проверка модели тоже: иначе первые кадры пропускаются и анимация «прыгает».

## Анимации
- Общий набор — `shared/.../Motion.kt`: `appear(index)` — появление снизу по очереди (шаг 45 мс, не больше 12 шагов); `pop` — выпрыгивает с пружиной (верный ответ, новое слово, «Засчитано»); `shake` — встряска (подсказка после ошибки, при уверенной ошибке сильнее; «Правильный ответ», «Модель нашла ошибку», «Модель: смысл другой»); `pulse` — дыхание главной кнопки экрана; `pressScale` и `pressable` — кнопки и строки сжимаются при нажатии; `countUp` — числа набегают с нуля; `RollingText` — символы прокручиваются, как на счётчике (номер шага, таймер отдыха, название темы).
- Переходы — `ScreenFlow.kt`: экраны сменяются сдвигом с затуханием, на главную — в обратную сторону. `screenKey` решает, что считать новым экраном: обновление того же экрана (загрузка модели на главной, тот же вопрос после ошибки) меняет содержимое без перехода. Шапка занятия (шаг, полоса, «Закончить») живёт вне перехода, поэтому полоса растёт, а не рисуется заново.
- `NeonBar` заполняется с нуля при появлении; смена темы плавно перетекает цветами палитры (`fading` в `Theme.kt`).
- Кнопки — только `NeonButton`, `NeonOutlinedButton`, `NeonTextButton`; нажимаемые строки — `Modifier.pressable`, а не `TextButton` и `clickable`: так нажатие везде пружинит одинаково.

## Лимит нового (М18)
- 12 новых в день — на день, а не на занятие: `ItemProgress.firstDay` — день первого изучения, план дня вычитает начатое сегодня. Знакомое по тесту уровня заводится `Engine.placeKnown` с `firstDay = null` и в лимит не идёт.
- Старые состояния (`SavedState.firstDaysRecorded = false`) один раз берут дни первого изучения из журнала (`LogReplay.firstStudyDays`).

## Калибровка и подгонка памяти (М2)
- Отдельной контрольной нет: каждый плановый повтор проверяет прогноз модели. `Calibration.of` проигрывает журнал `answers.jsonl` через FSRS: перед повтором известна вероятность вспомнить, после — вспомнили ли. Считаются только первые ответы дня (`grade != null`) по уже встреченным единицам.
- Итог: средний прогноз против доли вспомненного с 95% интервалом Вильсона и разбивкой по уровням прогноза; вывод — от `StudyConfig.minReviewsForCalibration` (30) повторов. Экран `Screen.Calibration`, ссылка «Точность прогноза памяти» на главной.
- Знакомое по тесту уровня пишется в журнал с `checkedBy = placement`: проигрывание восстанавливает ту же память, но эти записи не оцениваются. У тех, кто прошёл тест до этого, таких записей нет — их первый повтор просто считается первой встречей.
- Подгонка параметров: `engine/fsrs/FsrsOptimizer.kt` — порт оптимизатора py-fsrs 6.3.2 (log loss на повторах со второго дня, Adam 5 эпох, пачки по 512, шаг 0.04 с косинусным затуханием, обрезка по границам `Fsrs.LOWER_BOUNDS/UPPER_BOUNDS`, первые 64 повтора единицы, меньше 512 повторов — не подгоняет). Отличия: градиент — центральные разности вместо autograd, пачка — целые единицы. Ошибка сверена с py-fsrs до 1e-12 (`FsrsOptimizerVectors`); на одних данных наша подгонка и py-fsrs дают почти одно и то же (ошибка на новых повторах 0.4060 и 0.4055 при стандартных 0.4106).
- Решение принять — `study/calibration/PersonalFit.kt`: последние 20% повторов (по дням) откладываются, подгонка идёт на остальных, обе модели оцениваются на отложенных; лучше прежней — подгоняется заново по всем и принимается (`SavedState.fsrsParameters`, итог в `fsrsFit`). Первая попытка — с 640 повторов (512 + отложенные), дальше каждые 512 новых (`StudyConfig`).
- Запуск — в конце занятия, в фоне (`background` у `StudyController`). Принятые параметры пересобирают память всех единиц из журнала (`LogReplay.progress`), так что сроки повторов идут уже по новой модели. Единицы, начатые с теста уровня, в подгонку не идут: их история начинается с догадки, а не с первой встречи.
- Экран «Точность прогноза» показывает, чьи параметры в работе и как прошла последняя проверка на отложенных повторах. Сверху — вывод простыми словами («Модель знает вашу память», «Модель переоценивает вашу память»…) и фраза «обещала X%, вы вспомнили Y%»; та же фраза стоит в ссылке на главной (`Home.calibration`, `CalibrationSummary`, кэш на день).

## Правила
- Что, когда и сколько учить, решает только код движка. ИИ только проверяет свободные ответы; без модели свободный ответ ученик сверяет с образцом сам.
- Числа механик живут в `EngineConfig`, числа хода занятия — в `StudyConfig`. Метка механики и уровень доказательности каждого числа — в таблице «Настройки и их основания»; новое число добавлять и туда.
- Комментариев в коде нет (решение автора): понятные имена, короткие функции, маленькие файлы. Почему так сделано и форматы данных — в этом файле и в `docs/mechanics.html`.
- У каждой механики свой тест. Новая механика: правило в docs, параметр в конфиге, код, тест.
- FSRS — порт py-fsrs 6.3.2. При изменении формул перегенерировать векторы: `scripts/fsrs_vectors.py` (Python 3.10+, `pip install fsrs==6.3.2`) печатает только случаи — их вставить в `FsrsVectors.kt` между заголовком и закрывающей скобкой; `python3 -I scripts/fsrs_optimizer_vectors.py > engine/src/commonTest/kotlin/com/jatta/engine/FsrsOptimizerVectors.kt` (`pip install 'fsrs[optimizer]==6.3.2'`, тянет torch) пишет файл целиком.
- Простой код: без DI-фреймворков, данные и функции вместо иерархий классов.

## Команды
```bash
export JAVA_HOME=/opt/homebrew/opt/openjdk@17/libexec/openjdk.jdk/Contents/Home
./gradlew :engine:jvmTest :study:jvmTest
./gradlew :androidApp:assembleDebug
./gradlew :androidApp:assembleRelease
./gradlew :shared:compileKotlinIosSimulatorArm64
```
Релиз: `assembleRelease` — R8 со сжатием, подпись отладочным ключом (ставится из файла, как Drop Tuner). ML Kit создаёт свои компоненты через рефлексию — в `androidApp/proguard-rules.pro` он сохранён целиком; без этого Gemini Nano молча ломается, а на эмуляторе этого не видно. Релизная сборка не отладочная: `run-as` в её данные не пускает. В GitHub-релиз кладём `Jatta.apk`, тег `vX.Y`, описание на русском.
Эмулятор: `$SDK/emulator/emulator -avd droptuner -no-audio` (SDK в `/opt/homebrew/share/android-commandlinetools`), затем `adb install -r androidApp/build/outputs/apk/debug/androidApp-debug.apk`.

## Окружение
- JDK 17 из Homebrew, системной Java нет. `local.properties` указывает на Android SDK.
- Версии: Kotlin 2.4.20, Gradle 9.7.1, AGP 9.1.1, Compose Multiplatform 1.12.1, compileSdk 37.
- Xcode не установлен: iOS-код компилируется, но для симулятора, сборки приложения и Foundation Models нужен Xcode.
- Gemini Nano работает только на поддерживаемых телефонах, не в эмуляторе.
